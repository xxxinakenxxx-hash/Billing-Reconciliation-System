# 請求書スキャン・MIMS突合 標準処理手順書
版：改訂案 v1.3（承認前）／元版：v1.2
目的：請求書PDFとMIMS仕入データを、件数・取引先・帳票形式に依存せず照合する。

## 1. 適用・基本原則
- ScanSnap取得PDF、電子請求書、続紙・明細を含む。原本は受領時点で正式保存し、改名・削除・上書きしない。
- 既存経理業務どおり**仕入先別合計を先に照合**する。対象範囲が対応し合計一致した仕入先は、原則として明細抽出・明細突合を行わず完了する。不一致・対応不明・低信頼は追加調査する。
- 仕入先名が一致しただけでは突合完了としない。請求金額とMIMS該当額の照合を必須とする。
- 原本ファイル名は識別・追跡専用で、社名・日付・金額の判定根拠にしない。
- 対象件数、期間、フォルダ、MIMS抽出条件、除外条件、保存先は毎回の実施条件票で指定し、本書に固定しない。

## 2. 入力
1. 原本PDF：原本Drive ID、ファイル名、全ページ数を保持。
2. MIMS仕入確定データ：仕入先コード・名称、対象期間、計上日、商品、発注No、税抜金額等。
3. 仕入先辞書：略称、旧字体、支店名、住所、電話、登録番号等。
4. 実施条件票：対象期間・請求締日・データ範囲・除外・命名例外・処理済み先・成果物先。

## 3. 標準処理フロー
| STEP | 処理 | 作業と出力 |
|---|---|---|
| 1 | 実施条件・原本固定 | PDF一覧をページングして全件取得し、原本ID・件数・ページ数・MIMS対象データを確定する。原本は変更しない。 |
| 2 | 全ページ確認・分類 | すべてのPDFの全ページを確認し、請求書本体・続紙・明細・裏面・社内資料などをページ単位で分類する。全ページの明細文字起こしは要求しない。 |
| 3 | 請求書単位整理 | 1PDF内の複数請求書・複数仕入先を分け、帳票IDと原本ID・ページ範囲を紐付ける。 |
| 4 | 仕入先・請求日・請求額の特定 | 会社名だけでなく住所・電話・登録番号・口座等を用いて仕入先を照合し、本文から請求日と照合対象の税抜請求額を取得。税額・税込額も区別する。低信頼は対象ページ・領域を再確認する。 |
| 5 | 処理用PDF別名保存 | 仕入先・請求日を確定したものから、原本を維持して別名コピーを保存。原則 `YYYYMMDD_仕入先名.pdf`。重複・日付不明は実施条件票の規則に従い、原本IDと保存先IDを記録。 |
| 6 | 仕入先別請求額集計 | 対象期間・締日・税区分を揃え、1社複数請求書は対象請求額を合算。対象外・不確定は別管理。 |
| 7 | MIMS仕入先別合計抽出 | 対象期間・仕入先コード・金額基準を揃えてMIMS仕入先別税抜額を集計。対応範囲の差異を確認する。 |
| 8 | 合計先行突合 | 仕入先別に請求額合計とMIMS該当合計を比較。差額0で範囲・金額信頼性が確認できれば「合計一致」。単なる偶然一致をOCR検証完了の代用にしない。 |
| 9 | 不一致・未確定の再調査 | 複数締日、請求書がMIMS月計の一部となるケース、対象期間のずれ、誤読を確認。MIMS明細の部分集合一致を調べ、必要なら再OCR。合計一致の仕入先は詳細処理へ進めない。 |
| 10 | 対象限定の全明細抽出・検算 | STEP9で未解消の請求書に限り、処理用PDFから請求番号・商品・規格・数量・単位・単価・金額・値引・税区分・税抜・税・税込を抽出。明細合計、税抜＋税＝税込等を検算し、原本記載に照らす。 |
| 11 | MIMS明細突合・差異特定・判定 | 対象明細を発注No・商品・数量・単価・金額で比較し、不足・過剰・数量差・単価差を特定。一致／一部一致／不一致／対象外／要人確認を帳票IDで記録。 |
| 12 | 成果物作成 | 請求書一覧・必要対象の明細一覧→MIMS突合表→差異一覧→実施結果レポートの順で作成。合計一致の明細欄は「詳細抽出対象外」と明記し、架空の行を作らない。 |
| 13 | 保存・報告 | 原本PDF・処理用PDF・請求書金額・抽出済み明細・MIMS突合・判定と成果物を帳票IDで追跡可能にし、全件状態を確認して報告。 |

## 4. 判定規則
- **合計一致**：同一仕入先・同一対象範囲・同一税基準で請求合計＝MIMS合計、かつ読取の信頼性を確認。明細確認省略。
- **一部一致**：MIMS月計と請求書総額は異なるが、請求対象に対応するMIMS明細部分集合は一致。対応行を記録。
- **不一致**：対応範囲と読取を再確認しても差額が存在する。明細差異と未特定理由を記録。
- **対象外**：非請求書等。理由を記録。
- **要人確認**：再確認・再OCR・候補照合でも金額または対象範囲を確定できない。候補と理由を残す。
- 合計一致は**OCRの正確性そのものの証明ではない**。金額の転記は原本表示との照合、税区分、締日、二重計上、範囲の整合確認を要する。

## 5. 品質ゲート
- G1：全PDFの全ページを分類し、ページ漏れ・複数請求書混在を確認する。
- G2：確定した仕入先・請求日は本文と複数根拠で検証し、処理用PDFを別名保存して原本IDを追跡できる。
- G3：請求額・税抜/税込区分と対象範囲を検証する。全件明細抽出は合計突合の前提にしない。
- G4：社名一致のみで金額一致と判定しない。
- G5：月計不一致で即不一致とせず対象明細の部分集合一致を調べる。
- G6：未解消の不一致は全明細を抽出・検算し、明細差異をできる限り特定する。
- G7：必要な一覧とMIMS突合表が揃うまで結果レポートを作らない。
- G8：全対象帳票に一致・一部一致・不一致・対象外・要人確認等の状態が付くまで完了としない。
- G9：原本値、OCR値、集計値、MIMS値の出所を識別し、根拠不明の自動修正や欠損補完をしない。

## 6. 成果物
1. **請求書一覧**：帳票ID／原本ID／原本名／ページ範囲／処理用PDF ID／仕入先／請求日／請求額税抜／税額／税込額／OCR信頼度／原本確認／明細抽出の要否。
2. **請求書明細一覧（対象限定）**：帳票ID／商品／規格／数量／単位／単価／明細額／値引／税区分／税抜計／税／税込計／根拠ページ／信頼度。合計一致で未抽出の帳票は「未抽出（規定による省略）」とする。
3. **MIMS突合表**：帳票IDまたは仕入先集計ID／期間／請求額／MIMS額／差額／判定／MIMSコード／対象行／突合根拠／確認理由。
4. **差異一覧**：帳票ID／商品・伝票／請求数量・単価・金額／MIMS数量・単価・金額／差額／差異区分／対応先。
5. **実施結果レポート**：対象範囲・件数・合計一致件数・一部一致・不一致・要確認・明細確認省略件数・誤読例・残件。

## 7. 実施条件票
対象期間／原本保存先／実PDF件数と総ページ数／MIMSファイル・期間／締日・税基準／除外条件／処理済み保存先／成果物保存先／日付不明・同名重複時の命名規則／実施日・担当。

## 8. 運用上の注意
- 全ページ**確認**は全ページ**明細OCR**とは異なる。画像PDFの全ページ分類は維持する。
- 社名や請求額が判別できない帳票は推定値で強制一致にしない。
- 実データはこのGitHubリポジトリには格納しない。
- 本案の正式適用には業務責任者の承認が必要である。
