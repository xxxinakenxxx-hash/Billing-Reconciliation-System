# 経理買掛突合 Work実行処理 詳細設計案
状態：設計案／対象：請求書PDFとMIMS仕入確定データの照合／業務規則：改訂案標準処理手順書を参照

## 1. 設計目的・根拠
- 既存経理業務は仕入先別の合計を先に照合し、合わない場合に商品明細を調査する（打合せ記録・現状整理）。
- 旧SOP v1.2の全件・全明細抽出先行は、画像PDF大量処理において負荷を増やすため、合計先行に改める。
- 前回実施ログでは原本187PDF、先頭10PDFは56ページ。総ページ数は未確定。Drive取得100件を全件と誤認した履歴がある。
- WorkのRAM・画像キャッシュ・コンテキスト内部動作と停止原因は未計測。以下は内部実装を断定しない、**実行時に要求する制御仕様**である。

## 2. データ区分と生存期間
| データ | 保管先・形 | 破棄・解放条件 |
|---|---|---|
| 原本PDF | Drive原本ID・正式保存 | 削除・改名・上書き禁止 |
| 原本一覧 | ID／ファイル名／ページ数／処理状態の永続台帳 | 全工程で維持 |
| ページ画像 | 現在参照中のページ画像のみ一時領域 | 分類・対象項目読取・検証完了後に閉じる。原本は残す |
| OCR一次抽出 | ページ・座標／項目名／値／信頼度／原本照合状態 | 確定情報を台帳保存。会話には全ページ本文を転載しない |
| 処理用PDF | Driveで原本とは別のファイルID | 保持、原本IDに関連付ける |
| 請求書単位ヘッダー | 帳票ID・社名・日付・税抜／税／税込・根拠ページ | 永続保存、以後は必要な列のみ参照 |
| 明細OCR | 合計不一致など追加調査対象のみ | 明細構造化後、画像・一時出力を解放 |
| MIMS対象データ | 正本から抽出した集計・必要明細 | 比較時は必要な仕入先・期間に絞る |
| 実施ログ | 永続ログ（STEP・対象ID・実測時間・結果・エラー） | 会話内では要約・現在位置のみ参照 |

**メモリ制約の考え方**：同時に扱うのは全187PDFの画像ではなく、現在確認する少数ページと最小限の判定根拠。Workに実際の強制メモリ解放APIがあるとは仮定しない。ファイルの解放と会話コンテキストの縮小は同義ではない。

## 3. 処理アルゴリズム
### A. 全件把握（SOP STEP1）
1. Driveフォルダ一覧を継続トークン／ページングを使って終端まで取得し、最後のページが空か次ページトークンなしであることを確認。
2. 原本フォルダ直下からPDFのみ抽出。原本IDをキーに重複排除。サブフォルダを対象に混ぜない。
3. 取得件数・入力範囲・MIMS正本ID・処理状態を台帳に確定。**最初からPDF全件の画像を開かない。**

### B. 帳票構造・合計の取得（SOP STEP2〜4）
1. 全PDFを全ページ確認して請求書・続紙・裏面・非請求書を分類する。複数帳票のページ境界を特定して帳票IDを割り当てる。
2. 読取対象は原則、仕入先、請求日、税抜請求合計、税額、税込額、必要な締日・請求先・登録番号の根拠に限定。**全明細の行OCRはしない**。
3. 仕入先の表記揺れは辞書・住所・電話・登録番号等で検証。低信頼の項目だけ該当ページ・領域の画像を再解析する。
4. 金額は必ず税抜・税・税込を識別し、原本の表示値と抽出値を照合。合計が合ったことのみを正読根拠にしない。
5. 帳票IDごとのページ参照・抽出値・信頼度・検証結果を保存。詳細なOCR全文を作業会話へ持ち越さない。

### C. 処理用PDF（STEP5）
- 社名・日付確定後に `YYYYMMDD_仕入先名.pdf` の別名コピーを保存。原本のファイル名・バイト列は変更しない。
- 日付不明・同名重複の命名は実施条件票に従い、未定なら勝手に補完しない。
- 原本IDと処理用IDの対応を保存し、再実行時には既存コピーの対応を照合して二重作成を避ける。

### D. 合計先行（STEP6〜9）
1. 対象期間・税区分・締日を揃え、請求書ごとの税抜対象額から仕入先別請求合計を算出する。1社に複数請求書なら合算する。
2. MIMS正本から同じ仕入先・対象期間の税抜合計を抽出する。
3. 両合計を比較し、範囲が対応しOCR原本照合を通過し差額0の仕入先は「合計一致」。詳細OCRは不要。
4. 差額がある場合は、まず請求範囲や締日・MIMS部分集合を確認。該当明細集合が一致する場合は一部一致として根拠を残す。
5. 読取不確実な合計は金額再OCRを優先。数字を推測補完して差額0にしない。

### E. 不一致のみ全明細（STEP10〜11）
1. 未解決の仕入先に紐付く帳票だけ、処理用PDFの明細ページを対象として行構造・数量・単価・金額・値引・税区分を抽出。
2. 明細合計・税抜・税・税込の整合を検算。原本画像と疑わしい金額・行欠落を再照合。
3. 仕入先・期間・発注No・商品・数量・単価・金額によってMIMS候補を段階的に絞る。月計不一致だけで不一致確定しない。
4. 差異の行・区分・金額・未特定理由を出し、帳票IDとMIMS行IDを保存する。
5. 合計一致の仕入先については全明細の欄を「規定により未抽出」と明記し、欠落や処理失敗と混同しない。

### F. 成果物（STEP12〜13）
- 帳票一覧、対象限定の明細一覧、MIMS突合表、差異一覧、結果レポートを保存データから生成する。未抽出明細を生成しない。
- 最終時に原本件数、分類済みページ数、帳票ID数、処理用PDF対応、全帳票判定、差額の整合、ログ証跡を照合。
- WorkからMIMSの仕入確定値や支払いを変更しない。

## 4. バッファ・I/O・再実行制御
- 全件ファイル一覧はID等のメタデータのみ保持し、PDF画像は開くときだけ展開する。
- ページ画像はOCR前に必要解像度で生成。巨大な全ページ画像配列を同時に展開しない。
- 検証済みの項目は直ちに永続化し、以後の工程ではその項目だけを参照する。再読取は低信頼または矛盾がある該当領域に限定。
- 画像バッファ・一時OCR本文は保存確認後に参照を手放す。保存した事実とメモリが解放された事実を混同しない。
- 進捗台帳は「未着手／処理中／検証待ち／完了／再処理対象」と処理段階を区別し、帳票IDと原本IDで冪等に管理する。
- 例外発生時は原因・原本ID・ページ・処理段階をログし、対象全件を最初から再処理しない。
- Workの内部コンテキスト制御は確認されていない。利用可能な機能がないなら、自動的に縮小・解放されると記述しない。

## 5. 品質確認と実測
| 試験 | 合格基準 |
|---|---|
| Drive全件取得 | ページング終端を確認し、対象全IDを台帳化。100件上限誤認なし |
| 多ページ・複数請求書 | 全ページ分類、帳票IDと原本ページ対応が漏れない |
| 金額OCR | 税抜・税・税込を独立抽出。原本照合結果が記録される |
| 合計一致 | 対象範囲・税基準一致の確認後に明細OCRを省略 |
| 月計不一致 | 明細部分集合を検討し、即不一致判定をしない |
| 不一致 | 対象限定の明細OCRと算術・原本検算、MIMS差異行まで追跡 |
| 再実行 | 既処理用PDFや明細の重複作成なし。中断位置から再開可能 |
| 性能 | PDF件数・ページ数、OCR対象ページ、再OCR件数、経過時間、画像処理の同時数、取得可能ならピークRAMを記録。未計測なら未計測とする |

## 6. 変更管理・未決事項
- 本文は設計案であり、本番運用の正本改訂と処理方式採用には承認が必要。
- 画像PDFの全ページ分類は維持するが、全件の明細抽出は行わないため旧SOP v1.2のSTEP6/7・G3から変更となる。
- 要確認：対象期間と締日、MIMS集計単位、税抜基準、同名PDFの命名例外、帳票ID採番、OCR原本照合の具体方式、Workで実行可能なメモリ計測手段。
- OCRエンジンや外部サービスの新規導入を確定事項として扱わない。具体的なツールは環境確認後に決める。
